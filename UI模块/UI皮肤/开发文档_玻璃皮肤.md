## 1. 架构定位与铁律

### 1.1 UI 模块定位

UI 模块只是可视层/界面层，不是业务模块的父级。

正确口径：

- 框架模块：基础运行、注册、加载、服务、事件、数据共享底座。
- UI 模块：可视层，负责呈现和通用交互。
- 业务模块：K线模块、世界杯模块、指标模块、K线形态识别模块、回测模块等，都是独立业务模块，接入框架模块，并按需向 UI 模块提供页面/视图/交互。

玻璃皮肤只负责 UI 外观和通用入口，不直接承载业务逻辑。

### 1.2 皮肤与主题不能混淆

当前源码明确写死：

```swift
public final class GlassSkin: NSObject, UISkinProtocol {
    public let skinId = "com.app.glass"
    public let skinName = "玻璃皮肤"
    public let skinVersion = "3.0.0"
}
```

关键原则：

- 玻璃皮肤始终是 `com.app.glass`。
- 浅色、深色、高对比度、红色色盲、绿色色盲是玻璃皮肤内部视觉主题，不是把皮肤切走。
- 主题设置按钮点击后，仍保持：

```swift
UserDefaults.standard.set("com.app.glass", forKey: "com.xianrenzhilu.skin.currentSkinId")
```

内部主题写入：

```swift
com.xianrenzhilu.theme.currentThemeId
com.xianrenzhilu.glass.visualThemeId
com.xianrenzhilu.glass.visualSkinId // 兼容旧键，语义已废弃
```

### 1.3 公共协议/公共模型

源码头部注释已明确：

- 皮肤文件只实现皮肤逻辑。
- 公共协议/公共模型引用 `UI-02_公共类型定义.swift`。
- 辅助文件只包含皮肤内部专用类/参数，禁止定义公共协议/公共模型。

后续禁止在这两个文件里重复定义公共 UI 协议、统一注册表协议、业务模块协议。

## 2. `GlassSkin` 主入口

### 2.1 基础属性

```swift
public let skinId = "com.app.glass"
public let skinName = "玻璃皮肤"
public let skinVersion = "3.0.0"
```

内部弱引用/状态：

| 属性 | 说明 |
|---|---|
| `mainWindow` | 当前应用皮肤的窗口。 |
| `rootView` | 当前应用皮肤的根内容视图。 |
| `toolbarView` | 顶部玻璃功能栏。 |
| `settingsPanelView` | 当前打开的设置面板。 |
| `edgeGestureView` | 右侧边缘手势视图。 |
| `settingsOutsideClickMonitor` | 设置面板外点击关闭监听。 |
| `resizeObserver` | 窗口 resize 监听。 |

`deinit` 会移除外部点击监听和 resize observer，避免监听泄漏。

### 2.2 `apply(to window:)`

当前窗口应用逻辑：

1. 保存 `mainWindow`。
2. 设置标题为 `仙人指路`。
3. 隐藏标题文字：`titleVisibility = .hidden`。
4. 标题栏透明：`titlebarAppearsTransparent = true`。
5. 禁止内容区拖动窗口：`isMovableByWindowBackground = false`。
6. 窗口背景透明：`backgroundColor = .clear`、`isOpaque = false`。
7. 开启窗口阴影：`hasShadow = true`。
8. 清空原生 toolbar：`window.toolbar = nil`。
9. macOS 11+ 使用 `.unifiedCompact`。
10. 设置最小尺寸：`800 × 600`。
11. 根据玻璃内部主题设置 `window.appearance = GlassThemeHelper.nsAppearance()`。
12. 延迟对齐红绿灯按钮。

重点：

- 当前不是原生 `NSToolbar` 实现，而是自绘 `GlassToolbarView`。
- 窗口移动只允许在功能栏空白区域触发，由 `GlassToolbarView.mouseDown -> window.performDrag(with:)` 处理。
- 内容区点击/拖动不能移动窗口。

### 2.3 `apply(to view:)`

根视图应用逻辑：

1. 保存 `rootView`。
2. 开启 layer。
3. 设置 `view.appearance = GlassThemeHelper.nsAppearance()`。
4. 根层背景透明。
5. 根内容层裁剪窗口圆角：`windowCornerRadius = 14`。
6. 移除重复玻璃 chrome。
7. 确保根背景玻璃材质。
8. 确保功能栏。
9. 确保内容容器。
10. 确保右侧边缘手势。
11. 安装窗口 resize observer。
12. 执行布局。

根视图内当前受控 identifier：

| identifier | 说明 |
|---|---|
| `glass.root.material` | 根背景材质层。 |
| `glass.toolbar` | 顶部功能栏。 |
| `glass.edgeGesture` | 右侧边缘手势层。 |
| `glass.content.view` | 内容容器。 |

`removeDuplicateGlassChrome` 只去重这些受控视图，避免重复叠加材质层。

## 4. 主题系统实际逻辑

### 4.1 当前主题 ID 来源

`GlassThemeHelper.currentThemeId()` 读取顺序：

1. `com.xianrenzhilu.glass.visualThemeId`
2. `com.xianrenzhilu.theme.currentThemeId`
3. `com.xianrenzhilu.glass.visualSkinId`（兼容旧键）
4. 默认 `built-in-light`

读取后会调用 `normalizeThemeId`。

### 4.2 主题 ID 兼容映射

| 输入 | 归一化结果 |
|---|---|
| `com.app.light` / `built-in-light` | `built-in-light` |
| `com.app.dark` / `built-in-dark` | `built-in-dark` |
| `com.app.highContrast` / `com.app.high-contrast` / `built-in-high-contrast` / `built-in-highcontrast` | `built-in-highcontrast` |
| `com.app.protanopia` / `built-in-protanopia` | `built-in-protanopia` |
| `com.app.deuteranopia` / `built-in-deuteranopia` | `built-in-deuteranopia` |
| 其他 | 原样返回 |

### 4.3 深浅外观判断

`GlassThemeHelper.isDarkAppearance()` 当前逻辑：

- `built-in-dark` → true。
- `built-in-light`、`built-in-highcontrast`、`built-in-protanopia`、`built-in-deuteranopia` → false。
- 其他未知主题 → 根据 `NSApp.effectiveAppearance.bestMatch(from: [.aqua, .darkAqua])` 判断。

### 4.4 `nsAppearance()`

`GlassThemeHelper.nsAppearance()` 当前逻辑：

| 主题 | 返回 |
|---|---|
| `built-in-dark` | `NSAppearance(named: .darkAqua)` |
| `built-in-light` / `built-in-highcontrast` / `built-in-protanopia` / `built-in-deuteranopia` | `NSAppearance(named: .aqua)` |
| 其他 | `nil`，交给系统外观 |

重要：浅色主题会强制 Aqua，不能继续跟随系统深色材质。

### 4.5 “跟随系统”的当前真实行为

主题二级菜单里有 `system` 选项，但当前实现不是直接把 `system` 存成当前主题，而是在点击时立刻解析系统当前外观：

```swift
let isDark = NSApp.effectiveAppearance.bestMatch(from: [.darkAqua, .aqua]) == .darkAqua
resolvedThemeId = isDark ? "built-in-dark" : "built-in-light"
UserDefaults.standard.set(true, forKey: "com.xianrenzhilu.theme.followSystemEnabled")
```

然后仍写入解析后的 `built-in-dark` 或 `built-in-light`。

因此：

- 当前两个文件内没有看到系统外观变化监听逻辑。
- `followSystemEnabled` 当前主要用于二级菜单选中态显示。
- 如果要实现真正运行中跟随系统变化，需要在其他文件或后续补充系统外观变化监听，并在变化时更新 `visualThemeId` / 刷新玻璃视图树。

## 10. 卡片布局与 hover 逻辑

### 10.1 水平堆叠布局

`layoutCardsHorizontalStack()` 当前逻辑：

- `startX = 20`
- `cardW = 426`
- `cardH = 240`
- 每张卡片 x：

```swift
x = startX + CGFloat(index) * cardStackOffset
```

- y 有轻微错落：

```swift
y = centerY + (CGFloat(index % 2) - 0.5) * 6
```

- rotation：

```swift
rotation = (CGFloat(index) - CGFloat(count) / 2.0) * cardStackRotation
```

- zPosition 初始为 index。
- `cardHostView` 总宽：

```swift
totalWidth = startX + cardW + CGFloat(count - 1) * cardStackOffset + 80
```

### 10.2 hover 命中

当前 hover 命中使用稳定区，不用正在动画的 frame：

```swift
stableHitFrame = card.baseFrame.insetBy(dx: -8, dy: -8)
```

目的：避免卡片正在跟随鼠标移动时，命中穿透到底层卡片或抖动。

### 10.3 hover 行为

当前最终行为：

- hover 只抽出当前卡片。
- 不再做停留后飘动/重排。
- 鼠标移动时只更新当前卡片跟随位移和 3D 倾斜。
- 离开卡片后只让当前卡片插回原位，不整组重排。

`animateHover(mousePoint:)`：

- 根据鼠标点计算 `dx/dy`。
- frame 变为 `baseFrame.offsetBy(dx: dx, dy: dy + hoverElevation)`。
- transform 包含：
  - `m34 = -1.0 / 700`
  - scale = `1.065`
  - x/y 方向 3D 倾斜。
- hover 动画时长 `0.10`，避免高频 mouseMoved 叠长动画导致乱跳。

### 10.4 hover 音效

`GlassSoundManager.shared.playHoverTick()`：

- 音效名：`Funk`
- 类型：`aiff`
- 冷却：`0.04s`
- 优先 `NSSound(named:)`，失败则从 `/System/Library/Sounds/Funk.aiff` 加载。

## 11. 主题二级菜单逻辑

### 11.1 打开条件

只有点击一级卡片 `id == "theme"` 时，打开主题二级大卡片。

注意：不是 hover 打开；必须点击。

### 11.2 overlay 设计

`showThemeExpandedOverlay(from:)` 当前设计：

- 创建一个新的 `GlassModuleCardView` 作为 overlay 副本。
- 不修改原卡片 hover/排列状态。
- overlay 放入 `clippedContainer` 顶层，不放在 `scrollView/cardHostView` 里，避免被滚动区裁切和事件穿透。
- zPosition = `220`。
- 先从源卡片在面板中的 frame 开始。
- 动画到放大目标 frame。
- 0.34 秒后调用 `configureThemeMenuContents()` 填充主题按钮。

目标尺寸：

```swift
targetWidth = max(cardWidth, clippedContainer.width - horizontalMargin * 2)
maxTargetHeight = max(cardHeight, clippedContainer.height * themeExpandedCardMaxHeightRatio)
naturalTargetHeight = targetWidth * cardHeight / cardWidth
targetHeight = min(maxTargetHeight, max(cardHeight, naturalTargetHeight))
```

### 11.3 overlay 点击监听

`installExpandedThemeClickMonitor()`：

- 点击 overlay 内部 → 放行给内部按钮处理。
- 点击 overlay 外但仍在设置面板内部 → 收回 overlay，并消费这次点击，避免穿透到底层一级卡片。
- 点击设置面板外 → 收回 overlay，但放行给外层设置面板关闭逻辑。

### 11.4 主题选项

当前二级菜单选项：

| 标题 | themeId | 图标 |
|---|---|---|
| 浅色 | `built-in-light` | `sun.max.fill` |
| 深色 | `built-in-dark` | `moon.fill` |
| 跟随系统 | `system` | `desktopcomputer` |
| 高对比度 | `built-in-highcontrast` | `circle.lefthalf.filled` |
| 红色色盲 | `built-in-protanopia` | `eye.fill` |
| 绿色色盲 | `built-in-deuteranopia` | `eye.trianglebadge.exclamationmark.fill` |

点击后：

1. 如果 themeId 是 `system`，根据当前系统外观解析成 `built-in-dark` 或 `built-in-light`，并设置 `followSystemEnabled = true`。
2. 否则归一化 themeId，并设置 `followSystemEnabled = false`。
3. 固定当前皮肤为 `com.app.glass`。
4. 写入当前主题 ID。
5. 调用 `UIUnifiedRegistry.shared.applyTheme(id: resolvedThemeId)`。
6. 更新按钮选中态。
7. `refreshGlassAppearanceTree()` 刷新已存在玻璃视图树。

### 11.5 运行中刷新树

`applyCurrentThemeAppearanceTree(from:)` 会递归：

- 设置 view.appearance。
- 如果是 `NSVisualEffectView`，同步 `effect.appearance`。
- 根据 identifier 更新根材质、toolbar、content 的 backgroundColor。
- 如果是 `GlassToolbarView`，调用 `refreshThemeAppearance()`。
- 如果是 `GlassSettingsPanelView`，调用 `refreshThemeAppearance()`。
- 如果是 `GlassModuleCardView`，调用 `refreshThemeAppearance()`。
- 如果是 `GlassThemeOptionButton`，调用 `refreshThemeAppearance()`。
- 标记 needsLayout / needsDisplay / layer.setNeedsDisplay。

这个刷新逻辑很关键：运行中切主题不能只改 UserDefaults，否则 NSVisualEffectView 仍会停留在旧外观，看起来像“切了一半”。

## 13. 右侧边缘手势 `GlassEdgeGestureView`

### 13.1 区域

- 位于根视图右侧。
- 宽度 `34`。
- 高度为内容区高度：`root.height - toolbarHeight`。
- identifier：`glass.edgeGesture`。

### 13.2 事件

支持：

- `swipe(with:)`
- `scrollWheel(with:)`

`scrollWheel` 逻辑：

- 只处理水平滚动：`abs(rawX) > abs(rawY)` 且 `abs(rawX) > 0.4`。
- 按 `event.isDirectionInvertedFromDevice` 转换为手指运动方向。
- 累加 `accumulatedX`。
- 超过 `edgeGestureTriggerThreshold = 34` 才触发。
- 触发冷却 `0.55s`。

方向：

| 手势 | 行为 |
|---|---|
| 向左 | `onSwipeLeft` → 打开设置面板。 |
| 向右 | `onSwipeRight` → 关闭设置面板。 |
