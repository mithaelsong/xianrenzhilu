### 1.2 核心设计原则（晓筱拍板，已锁定）

**多画布架构**：一个（币对 × 时间框架）= 一张独立画布
- 10个币对各开若干周期 → 几十张画布，各画各的，加载完就挂在那儿
- 切换币对/周期 = 只切"显示哪张画布"（isHidden/层级），**绝不重画**
- 每张画布只更新自己那根未闭合的最后一根K线
- 闭合K线是死数据，加载时就画好，永不重画
- 画布实时建立、实时销毁

## 3. K线运行逻辑

### 3.1 启动链路

```
AppDelegate.applicationDidFinishLaunching
  → KJXRZApplication.shared.start()
    → UIModuleEntry.shared.start()
    → KXUI08Entry.restorePanelIfNeededAfterLaunch()
      → 读取 UserDefaults "com.xianrenzhilu.modules.kline.enabled"
      → 如果 enabled: 延迟 0.6s 调用 KXUI08Entry.openPanel()
        → UIContainerFactory.shared.createContainer(identifier: "KL_Main")
        → KXUI09KLinePanelView 装入容器
        → klinePanel.restoreState(from: UIModuleStateModel)
        → klinePanel.installWorkspacePersistenceHooks()
```

### 3.2 实时数据流

```
OKX WebSocket (trades频道)
  → KX-SY-07 WebSocket执行器
    → KX-SY-08 实时K线运行时（单例，多币对分桶）
      → processTradesLocked（按币对|周期分桶聚合）
        → applyTradeToCurrentCandleLocked（O(1)更新high/low/close/volume）
        → persistAndNotifyLocked
          → ≥15m: 只进内存缓存（禁止写库）
          → <15m: 进KLLowTimeframeCache内存
          → post .KLRealtimeCandleUpdated（main线程）
            → KX-UI-12 applyRealtimeCandle（增量更新最后一根）
              → 只刷新蜡烛层可见区最后一根 + 实时价格线层
```

### 3.3 多画布管理器（KX-UI-09）

### 3.4 性能优化要点

- **实时增量刷新**：只更新最后一根K线，不走全量 refreshData
- **后台隐藏画布**：isHidden=true 时只更新数据不 setNeedsDisplay
- **指标去重计算**：O(N²) 对齐 → O(N) 字典预映射
- **错峰加载**：币对间静默200ms + orderedSymbols，避免并发峰值

## 4. K线数据加载逻辑

### 4.1 加载规则

| 场景 | 加载策略 |
|---|---|
| 首次打开某币对某周期 | 先查库 → 库有数据但不够根数 → 补差拉REST → 画好挂起 |
| 中途加周期 | 立即按表格根数请求REST |
| ≥15m周期 | 库为权威来源，REST补缺口，内存只留表格根数 |
| <15m周期 | 纯内存，从trades聚合，不写库 |
| 切换画布 | 已预建的画布直接 isHidden 切换，不再加载 |
| 往左拖（未到边缘） | 从缓存/库取历史，不请求 |
| 往左拖（到边缘） | 触发 before 游标分页请求REST |
