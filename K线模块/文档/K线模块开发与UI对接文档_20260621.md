**约定：**
- 内部 rawValue 中小时/天/周用小写（`1h/1d/1w`），真正发往 OKX 的 bar 值在 `KX-FN-12_OKX周期映射.swift` 中已是正确大写（`1H/1D/1W`）。请求映射一律走 KX-FN-12，**不要直接拿 rawValue 当 OKX bar 使用**。
- 已明确**不支持** `5d（5天）`、`2m（2分钟）`、`10m（10分钟）`——OKX 原生无此三种周期，禁止再次引入或私自聚合补回。
- 新增任何周期相关 `switch KXTimeframe`，必须穷举全部 17 个 case（或带 default），否则编译报「switch must be exhaustive」。

## 1. UI 模块对接标准（K线模块必须遵守）

依据 UI 模块总文档，K线模块作为业务模块必须遵守以下边界：

1. **业务模块不重复造 UI 通用能力**：窗口、容器、自适应、布局、工作区、主题、停靠、标签页、快捷入口等能力统一调用 UI 模块。
2. **公共 UI 类型来自 UI 模块公共定义**：UI 公共模型/协议以 `UI-02_公共类型定义.swift` 为准，K线模块不得在业务层复制 UI 公共协议。
3. **权威注册表是 `UIUnifiedRegistry`**：后续 K线功能入口、命令、服务注册应统一写入注册表或 UI 功能管理器。
4. **K线主面板不得创建独立 `NSWindow`**：应嵌入 `UIContainerView / GlassContentView`，由 UI 模块管理显示、自适应和工作区恢复。
5. **稳定容器 ID 是 `KL_Main`**：位置、大小、排列恢复必须使用稳定 ID。
6. **模块启用状态由设置面板卡片开关控制**：开关打开后启动自动显示；开关关闭后启动不显示，但保留历史布局/参数。
7. **业务状态通过 UI 工作区/状态模型持久化**：币对、周期、标签、视口、指标显示等由 K线导出，UI 模块统一保存恢复。
8. **AppKit 更新必须回主线程**：UI 入口和视图刷新必须在 MainActor/主线程执行。
9. **卸载/关闭必须解除订阅和监听**：NotificationCenter、事件总线、定时器、WebSocket 回调等必须可清理。

### 3A.3 当前启动链路逐步说明

1. `仙人指路/main.swift` 设置 `AppDelegate` 并运行 `NSApplication`。
2. `AppDelegate.applicationDidFinishLaunching` 调用：

```swift
await KJXRZApplication.shared.start()
```

3. `KJXRZApplication.start()` 完成框架注册、模块加载后启动 UI 模块：

```swift
try UIModuleEntry.shared.start(context: uiBootContext)
_ = registerUIFunctionFeaturesAtEntry()
KXUI08Entry.restorePanelIfNeededAfterLaunch()
```

4. `KXUI08Entry.restorePanelIfNeededAfterLaunch()` 读取 K线模块启用开关：

```swift
UserDefaults.standard.bool(forKey: "com.xianrenzhilu.modules.kline.enabled")
```

5. 如果开关打开，延迟 0.6 秒执行：

```swift
KXUI08Entry.openPanel()
```

6. `openPanel()` 查找当前可见主窗口和 `glass.content.view`。如果找不到玻璃内容视图，则 fallback 到 `mainWin.contentView`。
7. `openPanel()` 使用 `UISerializationManager.shared.restoredContainerFrame(identifier: "KL_Main", fallback:)` 恢复 K线容器位置/大小。
8. `openPanel()` 调用 `UIContainerFactory.shared.createContainer(...)` 创建 UI 模块容器，而不是创建独立 `NSWindow`。
9. 创建 `KXUI09KLinePanelView` 作为业务内容视图，加入 `KL_Main` 容器。
10. 调用 `klinePanel.restoreState(from:)` 恢复币对、周期、标签、视口。
11. 调用 `klinePanel.installWorkspacePersistenceHooks()` 安装退出/resize 保存 hooks。

### 3A.4 设置面板 K线卡片开关逻辑

设置面板中的 K线卡片不再是“一次性打开按钮”，而是模块启用开关：

```text
点击 K线卡片
  → KXUI08Entry.setPanelEnabled(!KXUI08Entry.isPanelEnabled())
  → enabled=true：写入 UserDefaults 并 openPanel()
  → enabled=false：写入 UserDefaults 并 closePanel()
```

开关 key：

```swift
com.xianrenzhilu.modules.kline.enabled
```

行为标准：

| 开关状态 | 当前点击后 | 下次启动 |
|---|---|---|
| 关闭 | 打开并显示 K线 | 自动显示 K线 |
| 开启 | 关闭 K线 UI 实例，但保留状态 | 不自动显示 K线 |

### 3A.5 位置、大小、排列恢复规则

权威容器 ID：

```swift
KL_Main
```

恢复位置/大小：

```swift
UISerializationManager.shared.restoredContainerFrame(identifier: "KL_Main", fallback: fallbackFrame)
```

保存位置/大小：

```swift
UISerializationManager.shared.saveContainerFrame(identifier: "KL_Main", frame: container.frame)
```

关键原则：

1. 位置/大小/排列属于 UI 模块职责。
2. K线模块只提供稳定 ID 和业务内容视图。
3. 不允许 K线模块另建一套 layout JSON 或自建窗口恢复系统。
4. 禁用 K线时只移除 UI 实例，不清除 `KL_Main` 的历史 frame。

### 3A.6 K线内部状态保存/恢复规则

状态写入 `UIModuleStateModel.configuration`。

当前关键状态键：

| Key | 含义 |
|---|---|
| `kline.activeInstID` | 当前交易对/币对，例如 `BTC-USDT` |
| `kline.activeTimeframe` | 当前周期，例如 `1H` |
| `kline.volumeSplitRatio` | 主图/成交量区域比例 |
| `kline.openTabs` | 已打开标签列表 |
| `kline.tabOrder` | 标签顺序 |
| `kline.candleWidth` | K线蜡烛宽度 |
| `kline.contentOffsetX` | 图表横向滚动偏移 |

导出入口：

```swift
KXUI09KLinePanelView.exportState() -> UIModuleStateModel
```

恢复入口：

```swift
KXUI09KLinePanelView.restoreState(from state: UIModuleStateModel)
```

保存触发：

```swift
installWorkspacePersistenceHooks()
```

当前监听：

- `NSApplication.willTerminateNotification`
- `NSWindow.didResizeNotification`

### 3A.11 常见问题排障路径

#### 问题 1：启动后 K线没有显示

检查顺序：

1. 设置面板 K线卡片开关是否开启。
2. `UserDefaults` key 是否为 true：`com.xianrenzhilu.modules.kline.enabled`。
3. `KJ-GL-00_主程序启动.swift` 是否在 UI 启动成功后调用 `KXUI08Entry.restorePanelIfNeededAfterLaunch()`。
4. `KXUI08Entry.openPanel()` 是否找到可见主窗口。
5. 主窗口 contentView 或 `glass.content.view` 是否存在。
6. `KL_Main` 是否已经存在但被错误移除或 frame 为 0。

#### 问题 2：K线位置/大小没有恢复

检查顺序：

1. 容器 identifier 是否仍为 `KL_Main`。
2. 是否调用 `UISerializationManager.shared.saveContainerFrame(identifier: "KL_Main", frame:)`。
3. 是否调用 `restoredContainerFrame(identifier: "KL_Main", fallback:)`。
4. 是否误把 fallbackFrame 每次覆盖保存 frame。
5. 关闭/resize 时 `installWorkspacePersistenceHooks()` 是否安装成功。

#### 问题 3：币对/周期/标签没有恢复

检查顺序：

1. `KXUI09KLinePanelView.exportState()` 是否包含对应 key。
2. `restoreState(from:)` 是否解析对应 key。
3. `KLUIStateKey` 是否和写入 key 完全一致。
4. 标签栏 `KXUI10PairTabBarView` 是否根据恢复状态刷新 tabs/activeTabID。
5. 图表 `KXUI12KLineChartView` 是否收到恢复后的 symbol/timeframe。

#### 问题 4：窗口缩放时 K线不跟随

检查顺序：

1. `KL_Main` 容器 autoresizingMask 是否包含 `.width`、`.height`。
2. `KXUI09KLinePanelView` 是否填满 container bounds。
3. `chartContainer` 和 `KXUI12KLineChartView` autoresizing/layout 是否正确。
4. `layoutPanelSubviews()` 是否在 layout 时被调用。

#### 问题 5：指标显示异常

检查顺序：

1. 指标是否存在于 `KX-FN-29_统一指标注册表.swift`。
2. 是否有 `KX-FN-32_专业指标协议.swift` 对应 schema/输出。
3. 是否通过 `KX-FN-34_指标Overlay适配器.swift` 转换为 overlay。
4. `KX-UI-19_图表Overlay渲染器.swift` 是否收到 overlay。
5. 指标服务层当前仍未完善，不能把指标层作为稳定验收依据。

## 6. 开发规范与后续模块接入模板

### 6.1 新增 K线 UI 能力时

1. 业务层只新增业务状态、业务计算、数据接口。
2. UI组件层只新增业务视图，不创建独立主窗口。
3. 需要显示到主界面时，统一走 `KXUI08Entry` 或后续 K线 UI 门面，嵌入 `KL_Main` 或 UI 模块分配的容器。
4. 需要保存状态时，实现 `exportState()` / `restoreState(from:)`，写入 `UIModuleStateModel.configuration`。
5. 需要保存位置/排列时，调用 UI 模块 `UISerializationManager` / `UIWorkspaceManager`，禁止自建平行布局系统。

### 6.2 新增 K线业务能力时

1. 数据查询、网络同步、缓存逻辑放在数据/网络/业务层。
2. UI 刷新通过状态快照、Notification 或 UI 事件总线触发，禁止数据层直接操作视图。
3. 新增跨模块能力优先定义协议/DTO，例如现有 `KLExternalCandleQuerying`、`KLOverlaySubmitting`、`KLAlertEventSubmitting`。
4. 新增命令入口后续应注册到 UI 模块命令面板，而不是散落在具体皮肤 private view。

## 10. 多画布架构与稳定性修复（2.0 · 2026-06-22 追加 · 权威）

> 本章固化 2026-06-22 多画布架构改造 + 一整轮切换/显示/崩溃 bug 修复。
> 详细改造背景另见同目录《K线多画布架构改造开发文档_20260621.md》。
> 铁律：改任何文件前先 `read` 确认真实行号（行号会漂移）。本章给逻辑/根因/方案/验收，不是免读源码的借口。

### 10.1 多画布架构（已落地，晓筱锁定方向）

核心设计：**一个（币对 × 时间框架）= 一张独立 `KXUI12KLineChartView` 画布**。

- 一个币对选 N 个时间框架 → 该币对 N 张画布；多币对各开若干周期 → 几十张画布并存，各画各的。
- **切币对 / 切周期 = 只切 `isHidden` + z-order，绝不重画闭合K线**。
- 每张画布只更新自己最后一根未闭合K线（实时跳动）；闭合K线加载时画好，永不重画。
- 画布实时建立（开周期建）、实时销毁（关周期/关币对销毁）。

**关键实现（KX-UI-09_OKX风格面板.swift）：**
- `canvasByKey: [String: KXUI12KLineChartView]`（key = `"币对|周期rawValue"`，关联对象存储）。
- `showCanvas(symbol:timeframe:makeVisible:)`：已存在直接显示不重画；不存在则新建 + `loadLatestCandlesFromDatabaseOrOKX` 加载一次。`makeVisible=true` 时 `for (k,c) in map { c.isHidden = (k != key) }` 只显示目标、隐藏其余。
- `prebuiltOnlyKeys: Set<String>`：标记"只预建未补缺口"的画布；用户真正切到时补一次 `syncTimeframe`。
- `scheduleVisibleCanvasPrebuild`：错峰预建当前币对可见周期（首张静置、其余慢铺），用 `canvasPrebuildGeneration` 代号机制丢弃过期预建。
- `destroyCanvas(symbol:timeframe:)` / `destroyCanvases(forSymbol:)`：销毁画布并同步清理 `prebuiltOnlyKeys` 脏标记。

**聚合器策略（KX-SY-08_实时K线运行时.swift）：** 保留全局单例 `KLOKXRealtimeKLineRuntime.shared`，不复制聚合器；关币对标签发 `unsubscribe(symbol:)`。隐藏画布完全不处理实时 tick（`installRealtimeObserver` guard `!isHidden`），聚合器把每根K线 upsert 进缓存，显示时 `resyncFromCacheOnShow` 一次性同步。

### 10.2 每币对独立的可见时间框架集合（隔离 bug 修复）

**根因：** 可见周期集合原是工具栏选择器单一全局属性 `visibleTimeframes`，所有币对共用；`timeframeByInstrument` 只存了每币对"选中的单个周期"，没存"可见集合"。给某币对加 5m，所有币对都多 5m。

**修复（KX-UI-09）：**
- 新增 per-币对存储 `visibleTimeframesByInstrument: [String:[KXTimeframe]]`（关联对象）。
- `visibleTimeframesForInstrument(_)`：未设过返回默认 `[15m,1h,4h,1d,1w,1M]`（每个新币对的原始集合）。
- `rememberVisibleTimeframes(_:for:)` 存回当前币对。
- `activeVisibleTimeframes()` 读当前币对自己的集合。
- `handleVisibleTimeframesChanged` 开头 `rememberVisibleTimeframes(timeframes, for: instID)` 只存当前币对。
- `switchInstrument` 切币对时 `selector.visibleTimeframes = visibleTFs` 恢复该币对集合（KX-UI-11 该 setter 只 normalize+relayout，不触发 onVisibleTimeframesChanged，无回环）。
- `forgetTimeframe`（关标签）同步清理。

**规则：** 新建币对默认显示 `15m/1h/4h/1d/1w/1M`；其余周期手动从"更多"弹层调出；增减只影响该币对。

### 10.3 切换后某周期空白 — 缓存覆盖完整数据（修复）

**根因（诊断日志铁证）：** 空白画布 `candles=2880`(数据全在) `isHidden=false`，但 `resyncFromCacheOnShow` 中 `candles = valid` 用稀疏 cache 无脑覆盖。持久周期(15m+)完整历史在画布自己手里，`KLLowTimeframeCache` 往往只有实时聚合几根 → 覆盖后空白。

**修复（KX-UI-12 resyncFromCacheOnShow）按数据量决策：**
- `candles` 为空：用 cache（cache 也空则 refreshData）。
- `valid.count >= candles.count`：cache 更全（低周期 memoryOnly 权威）→ `candles = valid` 整体替换。
- `valid.count < candles.count`：cache 更少（持久周期完整历史在画布）→ 保留画布数据，只 `refreshData()` 重画 + `applyLatestRealtimeCandleFromCacheIfAvailable` 补最新实时一根。

### 10.4 画布消失（inSuper=false）— UI-GL-70 点击置顶根本 bug（修复）

**根因（诊断日志 + 源码双证）：** 空白画布 `candles` 全在、`isHidden=false`，但 `inSuper=false`（脱离视图树）。源码真凶 `UI模块/UI功能/UI-GL-70_视图点击置顶.swift` `handleClickForBringToFront`：
```swift
targetView.removeFromSuperview()
targetView.superview?.addSubview(targetView)   // BUG: 上一行已 remove, superview 已 nil, addSubview 不执行 → 视图永久移出
```
每张画布都注册了该手势，点击/切换触发 → 画布消失。

**两层修复：**
1. **K线侧（KX-UI-09）**：showCanvas isNew 块删除 `canvas.addClickToFront()`；setupAllClickToFront 删除 `chartView.addClickToFront()`。多画布叠加靠 isHidden 切换，不需要点击置顶。
2. **UI公共模块（UI-GL-70，晓筱授权改）**：
```swift
guard let superview = targetView.superview else { return }
targetView.removeFromSuperview()
superview.addSubview(targetView)
```
影响评估：调用方含世界杯模块(递归全子视图)、K线(tabBar/toolbar/chartContainer)；修复是纯修复，恢复"置顶=移到同级最上层"正确语义，对所有调用方安全。

### 10.5 切换间歇性不刷新（修复）

**根因：** 多画布叠同一 container 靠 isHidden 切换，走 `(no redraw)` 路径，AppKit 隐藏视图变可见瞬间有时不立即重绘 / z-order 不确定 → 间歇"切了没显示，要再点"。

**修复（KX-UI-09 showCanvas）：**
- makeVisible 切 isHidden 后目标画布置顶：`container.addSubview(canvas, positioned: .above, relativeTo: nil)`（仅当 `canvas.superview === container`；macOS 原生 reorder，非 UI-GL-70 那种错误写法）。
- show cached 分支强制立即重绘：`canvas.needsDisplay = true; canvas.displayIfNeeded()`。

### 10.6 偶尔点击没反应 — 周期按钮频繁重建（修复）

**根因：** `KX-UI-11_时间框架选择.swift` `layout()` 每次都销毁重建所有周期 NSButton。macOS layout() 触发频繁（resize/子视图变化/切画布），点击若撞上重建瞬间（旧按钮已 remove、新按钮未接入响应链）→ 落空。

**修复（KX-UI-11 layout）：** 新增 `laidOutTimeframes`，周期集合不变时只更新现有按钮 frame，不销毁重建；集合变化（增减周期/resize 跨自适应阈值）才重建并更新 `laidOutTimeframes`。

### 10.7 ★App 崩溃★ — WebSocket 订阅数组并发（修复）

**根因（崩溃报告 .ips 栈确诊）：** `EXC_BAD_ACCESS / SIGSEGV`，栈顶 `Array.append → _consumeAndCreateNew ← KLOKXDefaultWSExecutor.subscribeMultiple ← subscribeOpenedTradesLocked`。`KX-SY-07_WebSocket执行器.swift` 的 `subscriptions: [KLOKXWSSubscription]` 被多 async task 并发 append/removeAll/读，**无锁**（类标 @unchecked Sendable 但实际未保护）。快速增删周期/切币对触发大量并发订阅 → 数组扩容竞争 → 内存损坏崩溃。

**修复（KX-SY-07）：** 新增串行队列 `subscriptionsQueue = DispatchQueue(label: "com.kline.ws.subscriptions")`（与 K线前端统一锁型号，**不用 NSLock、不引框架模块的锁**）。helper：`subscriptionsSnapshot()`(queue.sync 读快照)、`addSubscriptionLocked`(去重 append)、`removeSubscriptionLocked`(removeAll)。subscribe/subscribeMultiple/unsubscribe/restoreSubscriptions 全部改走 helper。网络 send 仍在锁外 await，只数组读写进队列，不阻塞 IO。

**并发规范（教训）：** 加锁/并发原语先查模块现有统一规范，保持型号一致。K线模块前端统一用 `DispatchQueue(label:)` 串行队列（缓存/运行时/DB/聚合/指标等），不自带型号、不跨层引框架锁。

### 10.8 查询/加载根数规则（已实现）

- **加载永远按表格根数倒查最新 N 根**（`KX-SJ-09 queryLatestCandles`：`ORDER BY open_time DESC LIMIT N` 后外层正序）。
- **查询是判断型**（`latestCandleTime` 用 `SELECT MAX(open_time)` 判断缺口），与加载分离。
- 权威根数表 `KX-FN-12 chartLoadCandleCount(for:) -> Int`：`1s=600/1m=240/3m=360/5m=288/15m=672/30m=336/1H=2880/2H~3M=1440`。
- `1W/1M/3M` 有限历史（总根数 1W≈454/1M≈104/3M≈35）：有缺口直接全量拉所有页（`isLimitedHistory`）。
- 缺口阈值：`gapCount>2` 才补 REST；`<=2` 不拉，最新未闭合根由 recent 快照兜底。
- `KX-FN-18 syncOneTimeframe` persistent 分支：latestCandleTime 判断 → loadCount → desiredOldest 决策 → fetchAllHistoricalCandles 补齐 → fetchRecentCandles 快照 → queryLatestCandles 倒查灌内存 → notifyMemoryUpdated 发 `.KXTimeframeMemoryUpdated`。
