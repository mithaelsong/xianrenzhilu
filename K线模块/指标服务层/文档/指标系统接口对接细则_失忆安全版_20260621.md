## 6. UI-12 应该怎么消费 KX-FN-25

### 6.1 新增 currentOverlayTarget()

UI-12 需要一个函数，把当前图表状态转成 `KLOverlayTarget`。

建议：

```swift
private func currentOverlayTarget() -> KLOverlayTarget {
    KLOverlayTarget(
        exchange: "OKX",
        instrumentType: currentInstrumentTypeForSymbol(symbol),
        instrumentID: symbol,
        timeframe: timeframe,
        appliesToAllTimeframes: false,
        tabID: nil
    )
}
```

当前 `KX-UI-12` 只有 `symbol` 和 `timeframe`，没有 `instrumentType` 和 `tabID`。第一阶段：

```text
instrumentType 可以先用 "SPOT" 或由上层传入。
tabID 可以先 nil。
```

但文档必须标注 TODO：后续从 `KLMarketType` 或 panel context 传入真实 instrumentType。

### 6.2 新增 reloadExternalOverlays()

UI-12 需要：

```swift
public func reloadExternalOverlays() {
    let target = currentOverlayTarget()
    let overlays = KLDefaultOverlayManager.shared.allVisibleOverlays(target: target)
    overlayRenderer.apply(overlays: overlays)
    indicatorChipLayer.apply(overlays: overlays)
}
```

第一阶段如果还没有 `overlayRenderer` 独立文件，可以先建 `KX-UI-19_图表Overlay渲染器.swift`，不要继续扩展旧 `IndicatorOverlayLayer`。

### 6.3 refreshData() 中必须调用

当前 `refreshData()` 做：

```swift
recalculateActiveIndicators()
layersData.forEach { ... }
rebuildIndicatorHeader()
updateRealtimeLine()
```

新链路应该变成：

```swift
layersData.forEach { ... }
reloadExternalOverlays()
updateRealtimeLine()
```

并逐步删除：

```text
recalculateActiveIndicators()
activeIndicatorLines
activeSubpaneLines
activeSubpaneBars
rebuildIndicatorHeader()
```

注意：迁移不能一次性删除导致编译失败。分阶段：

```text
第一阶段：新增 reloadExternalOverlays，不删旧逻辑。
第二阶段：MA 走新链路，确认渲染正常。
第三阶段：删除 MA 旧逻辑。
第四阶段：逐个删除其他旧指标临时逻辑。
```

### 6.4 addTechnicalIndicator 兼容入口怎么改

当前 `KX-UI-09` 调用：

```swift
chartView.addTechnicalIndicator(indicator)
```

短期可以保留这个 API，避免大范围改 UI-09。

但 `KX-UI-12.addTechnicalIndicator` 内部必须改成转发：

```swift
public func addTechnicalIndicator(_ indicator: KXTechnicalIndicator) {
    KXProfessionalIndicatorInstanceManager.shared.addIndicator(
        indicatorID: indicator.id,
        chartContext: makeChartContext()
    )
    reloadExternalOverlays()
}
```

也就是说：

```text
函数名可以暂时保留
函数内部不能再算指标
```

### 6.5 设置后刷新怎么通知 UI-12

第一阶段简单做法：设置面板拿到 chartView 或闭包：

```swift
onIndicatorChanged = { [weak chartView] in
    chartView?.reloadExternalOverlays()
}
```

更标准做法：NotificationCenter：

```swift
extension Notification.Name {
    static let KXIndicatorOverlayDidChange = Notification.Name("KXIndicatorOverlayDidChange")
}
```

指标实例管理器每次提交 overlay 后：

```swift
NotificationCenter.default.post(name: .KXIndicatorOverlayDidChange, object: nil)
```

UI-12 监听：

```swift
NotificationCenter.default.addObserver(
    forName: .KXIndicatorOverlayDidChange,
    object: nil,
    queue: .main
) { [weak self] _ in
    self?.reloadExternalOverlays()
}
```

规范：推荐 NotificationCenter，避免设置面板直接强依赖 UI-12。

```swift
private func yForPrice(_ value: Double, min: Double, max: Double, height: CGFloat) -> CGFloat {
```

# 17. 指标占用 K线面板空间 / Pane Layout Reservation 规范

## 17.1 为什么必须新增这个能力

晓筱补充了一个关键场景：

> 有些指标不是简单画在现有 K线图上，而是会占用 K线面板空间。比如 OKX 某些指标打开后，K线主图会往上抬，下面空出一块区域给指标显示参数/副图/指标结果；关闭指标后，K线恢复原状。

这说明指标插入 K线面板不只有 overlay，还包括 layout 协商。

当前已有 `KX-FN-25_跨模块叠加显示接口.swift` 主要解决：

```text
指标/形态/预测 等业务结果 → 提交标准 overlay → K线面板渲染
```

但它还没有完整解决：

```text
指标需要 K线面板让出一块空间
指标需要新增副图 pane
指标需要独立 Y 轴
指标关闭后释放空间
多个副图指标如何排布
同类副图指标是否共用 pane
```

所以必须新增/补强 **K线面板布局占位接口**。

---

## 17.2 指标插入 K线面板的两种类型

### 类型 A：纯 overlay 指标

这类指标不改变 K线布局，只叠加在已有 pane 上。

例子：

```text
MA：主图 line
EMA：主图 line
BOLL：主图 band + lines
SAR：主图 point
买卖点：主图 label/marker
支撑阻力：主图 horizontalLine
```

特征：

```text
不需要新增空间
不改变 candleLayer / volumeLayer 布局
只提交 overlay figure
关闭后只删除 overlay
```

### 类型 B：占用空间 / 新增 pane 指标

这类指标需要 K线面板为它分配区域。

例子：

```text
MACD：副图 pane，DIF/DEA/MACD柱
KDJ：副图 pane，K/D/J线
RSI：副图 pane，RSI线 + 30/70水平线
成交量类副图指标
链上类副图指标
某些指标参数展示区 / 统计面板
```

特征：

```text
需要 K线面板重新布局
可能压缩主图高度
可能压缩/移动量柱
需要独立 Y 轴或固定 Y 范围
关闭后要释放空间并恢复布局
```

---

## 17.3 当前 K线面板缺口

当前 `KX-UI-12_图表视图.swift` 的布局大致是固定结构：

```text
主图 candleLayer
量柱 volumeLayer
分隔线 splitterLayer
价格轴 / 时间轴
十字线 / 实时价格线
```

当前临时实现曾经把副图指标画到 `volumeLayer` 区域，甚至隐藏 volumeLayer，这是错误行为。

明确禁止：

```text
❌ 副图指标直接覆盖 volumeLayer
❌ 添加 MACD/KDJ/RSI 时隐藏量柱
❌ 指标自己改 candleLayer.frame
❌ 指标自己改 volumeLayer.frame
❌ 临时用 subpaneLayer 盖在量柱上
```

正确做法：

```text
指标向 K线面板提交布局需求
K线面板 pane manager 统一重新布局
K线面板给指标一个正式 pane 区域
指标 overlay 渲染到该 pane
关闭指标后 pane manager 回收空间
```

---

## 17.4 必须新增：指标布局需求模型

建议新增到 `KX-FN-25_跨模块叠加显示接口.swift` 或新文件：

```text
K线模块/业务功能层/KX-FN-36_图表Pane布局申请接口.swift
```

推荐新增独立文件，避免 KX-FN-25 过大。

### 17.4.1 Pane 类型

```swift
public enum KLChartPaneKind: String, Codable, Sendable {
    case main        // K线主图
    case volume      // 固定量柱区
    case indicator   // 指标副图区
    case annotation  // 浮动标注层，不占布局
    case reserved    // 指标特殊参数/统计显示区
}
```

### 17.4.2 Pane 位置策略

```swift
public enum KLChartPanePlacement: String, Codable, Sendable {
    case overlayMain       // 叠加主图，不占空间
    case overlayVolume     // 叠加量柱，不占空间
    case belowMain         // 主图下方、量柱上方
    case aboveVolume       // 量柱上方
    case belowVolume       // 量柱下方
    case bottom            // 图表底部
    case floating          // 浮动，不占布局
}
```

### 17.4.3 Pane 高度策略

```swift
public enum KLChartPaneHeightPolicy: Codable, Sendable, Equatable {
    case fixed(Double)          // 固定高度，例如 90
    case ratio(Double)          // 占总高度比例，例如 0.18
    case minMax(min: Double, max: Double, preferred: Double)
    case contentDriven(min: Double, max: Double)
}
```

### 17.4.4 Pane Y轴策略

```swift
public enum KLChartPaneScalePolicy: String, Codable, Sendable {
    case priceScale     // 跟主图价格轴
    case volumeScale    // 跟量柱
    case auto           // 根据自身 visible values 自动 min/max
    case fixedZeroToHundred // RSI/KDJ 常见 0~100
    case centeredZero   // MACD 以 0 为中心
    case custom         // 指标自定义
}
```

### 17.4.5 布局申请对象

```swift
public struct KLChartPaneRequest: Codable, Sendable, Equatable, Identifiable {
    public let id: String
    public let moduleID: String
    public let instanceID: String
    public let indicatorID: String?
    public let title: String
    public let kind: KLChartPaneKind
    public let placement: KLChartPanePlacement
    public let heightPolicy: KLChartPaneHeightPolicy
    public let scalePolicy: KLChartPaneScalePolicy
    public let canStackWithSameKind: Bool
    public let preferredOrder: Int
    public let closeWhenNoOverlay: Bool
}
```

字段说明：

```text
id：pane 唯一 ID，例如 pane.indicator.<instanceID>
moduleID：indicator / pattern / prediction 等
instanceID：指标实例 ID
indicatorID：MA/MACD/KDJ 等，可选
kind：pane 类型
placement：放在哪里
heightPolicy：需要多少空间
scalePolicy：Y轴怎么缩放
canStackWithSameKind：是否允许多个同类指标共用 pane
preferredOrder：多个副图排序
closeWhenNoOverlay：删除/隐藏指标后是否自动移除 pane
```

## 17.6 指标如何申请 pane

### 17.6.1 MA 不申请空间

MA 是主图 overlay：

```text

```

### 17.6.2 MACD 申请副图区

MACD 添加时：

```swift

    id: "pane.indicator.\(instanceID)",
    moduleID: "indicator",
    instanceID: instanceID,
    indicatorID: "macd",
    title: "MACD",
```

然后 MACD 的 overlay 必须带 paneID：


如果 KX-FN-25 还没有 paneID 字段，必须补。

### 17.6.3 RSI 申请副图区

RSI：

```text
height preferred: 80~100
scalePolicy: fixedZeroToHundred
overlays: RSI line + horizontalLine 70 + horizontalLine 30
```

### 17.6.4 某些指标申请参数/统计区

如果某个指标像用户描述的 OKX 指标一样，需要在 K线面板下方让出一块参数/统计显示区：

```swift

placement: .belowMain 或 .aboveVolume / .bottom

scalePolicy: .custom
```

这类区域不能用 line renderer 画，应该由 K线面板开出一个 reserved pane，由指标提供 `label/table/customSnapshot` 显示。

### 17.7.3 applyPaneLayout 应该做什么

```swift
private func applyPaneLayout(_ layout: KXChartPaneLayout) {
    candleLayer.frame = layout.mainPane.plotFrame
    volumeLayer.frame = layout.volumePane.plotFrame
    priceAxisLayer.frame = layout.mainPane.axisFrame

}
```

# 18. 未来复杂指标/跨模块叠加场景的接口预留规范

## 18.1 为什么本章必须存在

晓筱补充：虽然现在还没有写到某些复杂指标，但接口必须提前设计好。不能等遇到特殊指标时再临时乱补。

已有历史决策要求：

1. K线模块必须提供统一标准跨模块接口。
2. 指标模块、形态识别模块、声音提示、回撤、预测、交易等模块都必须通过统一接口提交显示结果。
3. 禁止各模块直接改 K线 UI。
4. 禁止各模块直接写 K线数据库。
5. K线面板主图区和成交量区之间的白色细分界线必须可拖拽，布局比例要持久化。
6. K线模块是业务模块，UI模块是承载模块，不能把 K线业务能力塞到 UI模块里。

因此接口必须支持未来：

```text
普通指标线
副图指标
占用空间的指标
K线上标记
K线上标签
声音提示标记
回撤区域
预测区域
交易点位
画线工具
参数/统计面板
可拖拽 pane 分割器
pane 布局持久化
```

---

## 18.2 统一接口要分三层，不是一坨 overlay

为了避免未来失控，K线对外/对内标准接口必须分三层：

### 第 1 层：数据查询接口

文件已有：

```text
KX-FN-21_指标模块数据接口.swift
KX-FN-27_跨模块K线数据查询接口.swift
```

职责：给指标、形态、回撤、预测等模块提供 K线数据。

### 第 2 层：布局申请接口

建议新增：

```text
KX-FN-36_图表Pane布局申请接口.swift
```

职责：当外部模块需要 K线面板让出空间、新增副图、显示统计区时，通过这个接口申请。

### 第 3 层：叠加显示接口

已有基础：

```text
KX-FN-25_跨模块叠加显示接口.swift
```

职责：提交线、柱、带、点、标签、区域、交易标记、预测区等 figure/overlay。

三层关系：

```text
数据接口：我要算什么
布局接口：我要显示在哪块空间
叠加接口：我要画什么东西
```

不要把布局申请硬塞进 overlay，也不要把数据查询塞进 UI。

## 18.3 未来模块统一调用流程

所有业务模块都按同一流程。

### 18.3.1 纯标记模块，例如形态识别

```text
形态识别模块
→ 通过 KX-FN-21/KX-FN-27 获取 K线数据
→ 识别形态
→ 生成 label/marker overlay
→ 提交 KX-FN-25
→ 可选：提交声音提示事件 KX-FN-24/KX-FN-26
→ K线面板 reloadExternalOverlays 渲染
```

不需要 pane request。

### 18.3.2 副图指标，例如 MACD/RSI

```text
指标实例
→ 获取 K线数据
→ 申请 indicator pane（KX-FN-36）
→ 计算指标
→ 生成 histogram/line/horizontalLine overlay（KX-FN-25）
→ K线面板 reloadPaneLayout + reloadExternalOverlays
```

需要 pane request。

### 18.3.3 参数/统计型指标

某些指标打开后需要显示一个参数/统计面板，K线会让出空间。

```text
指标实例
→ 申请 reserved pane（KX-FN-36）
→ 生成 custom/table/label snapshot（KX-FN-25 或新增 reserved payload）
→ K线面板布局留出区域
→ 指标内容渲染到 reserved pane
```

### 18.3.4 回撤/预测模块

```text
回撤/预测模块
→ 获取 K线数据
→ 算出时间/价格范围
→ 提交 range/band/predictionZone overlay
→ 如果需要说明区，额外申请 reserved pane
→ K线面板渲染区域和说明
```

### 18.3.5 交易模块

```text
交易模块
→ 提交 tradeMarker/priceLine/textAnnotation
→ K线面板渲染买卖点、持仓线、订单线
→ 交易模块不直接操作 K线 UI
```

## 18.4 Pane 布局接口必须支持拖拽和持久化

历史要求：K线主图区和成交量区之间的白色细分界线必须可拖拽，拖动后布局比例持久化，重启恢复。

新增 pane 后，这个要求扩展为：

```text
主图 / 成交量 / 指标副图 / reserved 面板之间的分割线都应该由统一 Pane Layout Manager 管理。
```

### 18.4.1 Pane layout state

建议新增：

```swift
public struct KLChartPaneLayoutState: Codable, Sendable, Equatable {
    public let chartID: String
    public let symbol: String
    public let timeframe: KXTimeframe?
    public var mainRatio: Double
    public var volumeRatio: Double
    public var indicatorPaneRatios: [String: Double]
    public var collapsedPaneIDs: Set<String>
    public var updatedAt: Date
}
```

字段说明：

```text
chartID：图表/标签唯一 ID，可先用 symbol + timeframe
action：持久化布局时需要唯一键
mainRatio：主图高度比例
volumeRatio：量柱高度比例
indicatorPaneRatios：各副图 pane 高度比例
collapsedPaneIDs：被折叠/隐藏但未删除的 pane
```

### 18.4.2 Pane resize event

建议新增：

```swift
public struct KLChartPaneResizeEvent: Codable, Sendable {
    public let chartID: String
    public let paneID: String
    public let oldRatio: Double
    public let newRatio: Double
    public let timestamp: Date
}
```

### 18.4.3 UI-22 负责拖拽

建议文件：

```text
K线模块/UI组件层/KX-UI-22_图表Pane布局管理器.swift
```

必须负责：

```text
根据 pane requests 计算布局
生成分割器 frame
处理分割器拖拽
更新 ratio
触发 relayout
通知持久化
```

禁止：

```text
每个指标自己处理拖拽
每个 pane 自己改 frame
UI模块处理 K线业务 pane 比例
```

## 18.6 Pane request 与 overlay 的强关联

未来必须能回答：

```text
这个 overlay 画到哪个 pane？
这个 pane 是哪个指标申请的？
删除指标时要删哪些 overlay、释放哪个 pane？
```

因此统一 ID 规范必须提前定好。

### 18.6.1 ID 规范

```text
instanceID: indicator.<indicatorID>.<uuid>
paneID: pane.<moduleID>.<instanceID>
overlayID: overlay.<moduleID>.<instanceID>.<outputKey>
chipID: chip.<moduleID>.<instanceID>.<outputKey or summary>
```

示例：

```text
instanceID = indicator.macd.7F3A
paneID     = pane.indicator.indicator.macd.7F3A
overlayID  = overlay.indicator.indicator.macd.7F3A.dif
overlayID  = overlay.indicator.indicator.macd.7F3A.dea
overlayID  = overlay.indicator.indicator.macd.7F3A.hist
```

如果觉得重复，可简化，但必须稳定。

### 18.6.2 删除指标时的处理

```text
removeInstance(instanceID)
→ remove overlays where instanceID matches
→ release pane where instanceID matches
→ remove chips where instanceID matches
→ reloadPaneLayout if pane changed
→ reloadExternalOverlays
```

## 18.7 复杂显示类型预留

未来指标可能需要以下显示类型，接口必须预留。

### 18.7.1 K线上打标签

用于：形态识别、买点卖点、信号提示。

需要：

```text

price 可选
placement: aboveCandle/belowCandle/atPrice/paneTop
text
style
clickAction 可选
soundEventID 可选
```

### 18.7.2 K线上显示范围

用于：BOLL/Keltner/Donchian、回撤、预测区。

需要：

```text
upper/lower series 或固定 upper/lower
startTime/endTime
fillOpacity
borderStyle
```

### 18.7.3 K线上打点

用于：SAR、信号点。

需要：

```text
time
value
shape
size
color
```

### 18.7.4 指标参数/统计区

用于：用户提到的“打开指标后 K线抬上去，下面留空间显示参数”的指标。

需要：

```text
reserved pane request
content snapshot：text/table/key-value/customJSON
height policy
close behavior
```

建议 payload：

```swift
public struct KLReservedPaneContentPayload: Codable, Sendable {
    public let instanceID: String
    public let title: String
    public let rows: [KLReservedPaneRow]

public struct KLReservedPaneRow: Codable, Sendable {
    public let key: String
    public let value: String
    public let colorHex: String?
}
```

### 18.7.5 交互对象

未来画线工具、斐波那契、测量工具可能需要用户拖拽编辑。

这不应塞进普通 indicator overlay。

需要单独类型：

```text
interactiveDrawing
```

字段：

```text
controlPoints
hitTestPolicy
editable
snapToCandle
```

第一阶段可以只预留，不实现。

## 18.11 如果接口还不够怎么办

如果遇到新指标需要当前接口不支持的能力，不能直接在指标里硬写 UI。

必须按以下流程：

```text
1. 记录该指标需要的显示/布局/交互能力。
2. 判断属于：data / paneLayout / overlay / alert / interaction 哪一层。
3. 扩展对应接口。
4. 更新本文档。
5. 更新 KX-GL-02 注册表。
6. 编译通过。
7. 再实现该指标。
```

禁止：

```text
指标为了赶进度直接操作 UI-12 子视图。
```
