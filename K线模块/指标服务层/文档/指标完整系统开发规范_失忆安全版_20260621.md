# C. 标准调用链（必须按这个走）

## C1. 添加指标标准链路

用户点击指标菜单后：

```text
KX-UI-18 工具栏 / 指标菜单
    ↓
指标实例管理器 createInstance(indicatorID)
    ↓
读取该指标默认 params + styles + pane + figure schema
    ↓
通过 KX-FN-21 获取当前 K线标准 OHLCV 数据
    ↓
调用该指标自己的 calculator
    ↓
生成该指标自己的 output series
    ↓
根据 figure schema 转成 KLExternalChartOverlay 数组
    ↓
提交 KLDefaultOverlayManager.shared.submitOverlays(...)
    ↓
通知或触发 K线面板 reloadExternalOverlays()
    ↓
K线面板 allVisibleOverlays(target)
    ↓
OverlayRenderer 渲染 line/bar/band/point/label/range
    ↓
IndicatorChipLayer 显示顶部小标签
```

不允许：

```text
KX-UI-18 点击
    ↓
chartView.addTechnicalIndicator(indicator)
    ↓
KX-UI-12 内部计算 MA/MACD/KDJ
```

`addTechnicalIndicator` 可以保留成兼容入口，但内部必须转发到指标实例管理器，不得在 UI-12 内计算。

---

## C2. 修改指标参数标准链路

```text
点击指标小标签 / 设置按钮
    ↓
打开该指标实例的 settings panel
    ↓
用户修改 params/style
    ↓
指标实例管理器 updateInstance(instanceID, params/style)
    ↓
校验参数
    ↓
只重算该实例
    ↓
重新生成 overlays，使用同 overlayID 覆盖提交
    ↓
K线面板 reloadExternalOverlays()
    ↓
渲染更新
    ↓
小标签内容同步更新
```

要求：

1. 修改一个实例不能影响另一个实例。
2. 修改 MA(20) 不能影响 MA(60)。
3. 修改颜色/线宽不能触发无关指标重算，除非实现简单阶段统一刷新但结果不能错。
4. 参数必须真实参与计算。

---

## C3. 显隐标准链路

```text
用户点击 chip / menu 的显隐按钮
    ↓
指标实例 visible toggle
    ↓
KLDefaultOverlayManager.setOverlayVisible 或重新提交 visible=false
    ↓
K线面板 reloadExternalOverlays()
    ↓
该实例 figure 不再显示
    ↓
该实例 chip 隐藏或显示为禁用状态（由指标定义）
```

严禁：

```text
隐藏指标时隐藏 volumeLayer
隐藏指标时修改 candleLayer frame
```

---

## C4. 删除标准链路

```text
用户删除指标实例
    ↓
指标实例管理器 removeInstance(instanceID)
    ↓
KLDefaultOverlayManager.removeOverlay/removeAll instance overlays
    ↓
K线面板 reloadExternalOverlays()
    ↓
删除对应 figure 和 chip
```

要求：

- 只删该实例。
- 不删同指标其他实例。
- 不影响 K线、量柱、十字线、实时价格线。

# D. KX-FN-25 必须升级的内容

## D1. 为什么必须升级

当前 KX-FN-25 已经有接口雏形，但要承载所有指标，还缺标准 figure payload。

指标显示不止 line/band：

```text
MA/EMA: line
BOLL: band + 3 lines
MACD: histogram + 2 lines
KDJ: 3 lines
RSI: line + horizontal lines
SAR: points
形态识别: labels/markers
支撑阻力: horizontal lines/ranges
预测/回撤: range/band/zone
```

因此 KX-FN-25 要成为标准图形协议，而不是只存 indicatorLine。

## E5. 坐标转换规范

Renderer 不能自己猜坐标。

必须由 K线面板提供：

```text
time/date → candle index → x
price/value → y
pane bounds
visible start/end index
candle width
```

Line 绘制：

```text
series point.time 找 candle.openTime 对应 index
x = indexToX(index)
y = valueToY(value, paneScale)
```

Band 绘制：

```text
upper/lower 按同一 time 对齐
先画 fill polygon
再画 upper/middle/lower line
```

Histogram 绘制：

```text
baseline 默认为 0
y0 = valueToY(baseline)
y1 = valueToY(value)
正值颜色 upColor
负值颜色 downColor
```

Label 绘制：

```text
aboveCandle: y = candle.highY - offset
belowCandle: y = candle.lowY + offset
atPrice: y = valueToY(price)
```

## F2. 参数值不能永远用 Double

当前很多地方用 `[String: Double]`，不够。

必须支持：

```swift
public enum KXIndicatorParameterValue: Codable, Equatable, Sendable {
    case int(Int)
    case double(Double)
    case bool(Bool)
    case string(String)
    case option(String)
    case colorHex(String)
}
```

原因：

```text
source = close/open/high 是选项，不是 Double
lineStyle = solid/dashed/dotted 是选项，不是 Double
visible = Bool
color = Hex String
```

过渡阶段可以保留 Double 字典，但新 schema 必须支持多类型。

# R. 最终原则

请永远记住：

```text
指标系统不是画线功能。
指标系统 = 计算逻辑 + 参数设置 + 实例管理 + 显示定义 + 标准 overlay + K线渲染消费 + 设置后重算重绘。
```

K线面板不是指标业务模块：

```text
K线面板只渲染，不计算指标，不保存指标参数，不决定指标显示方式。
```

每个指标必须自己声明：

```text
我怎么算
我有哪些参数
我怎么设置
我输出什么图形
我显示在哪个 pane
我的标签怎么显示
我的样式怎么配置
我如何生成 overlay
```

只有这样，几十个指标才能不乱、不失忆、不重复造轮子。
